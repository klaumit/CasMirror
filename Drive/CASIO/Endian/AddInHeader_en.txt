Add-In header as a C structure

struct addinheader
{
  char addinsig[8]; /* = {0x00, 0xFF, 'C','A','S','I','O', 0x03}; */
  char model[4]; /* = {'Z','4','8','6'}; */
  char headerversion[4]; /* = {'0','1','0','0'}; */
  unsigned short status;
  unsigned short mode;
  char addinname[16];
  unsigned long addinlength;
  char compiledate[8]; /* e.g. "20020219" stands for Feb. 19th, 2002 */
  char compiletime[4]; /* e.g. "1246" is 46 minutes past 12 o'clock */
  char version[4]; /* "0120" stands for version 1.20 */
  char libdate[8]; /* e.g. "20000215" stands for Feb. 15th, 2000 */
  char libtime[4]; /* e.g. "0940" is 40 minutes past 9 o'clock */
  char libver[4]; /* e.g. "0100" stands for version 1.00 */
  unsigned long offsicon;
  unsigned long offslicon;
  char comment[64];
};


Add-In header fields

The Add-In header starts with a fixed signature of 8 bytes (offset
0x0000).

When installed on the PV the second byte (0xFF) works as a flag for
deleted Add-Ins. Deleted Add-Ins are marked with a 0x00 at this
location.

Four bytes are used as a model descriptor (offset 0x0008).

Observed model descriptors are "Z486" for Add-Ins working on all PV
models, "Z488" for Add-Ins working only with PV 750(+), "G500" for
Add-Ins working only for PV-S460/S660.

PVM.exe will check this value and will refuse to install Add-Ins on
wrong models.

Four bytes probably describe the header version in an ASCII
representation (offset 0x000C). There is only one observed value
"0100".

Two bytes represent the status (offset 0x0010). For regular Add-Ins
this value is always 0x0101. Inside PVOS also values of 0xFF01,
0xFF02, and 0xFF81 can be found.

Another two bytes represent mode and submode of Add-In (offset 0x0012).

The mode for Add-Ins (as produced by the SDK) is always 0x08FF, this
is a main mode of 0x08 and an undefined sub mode. The submode will be
changed to a value from 0x01 to 0x0F during installation.

The name of the Add-In is hold in 16 bytes (offset 0x0014), it must be
terminated by 0x00 so that the longest possible name can have 15
characters.

A double word holds the length of the Add-In (offset 0x0024).

The date of compilation is stored as the ASCII representation of year,
month and day (offset 0x0028).

Time of compilation is stored as the ASCII representation of hour and
minute (offset 0x0030).

The version of the Add-In is hold as the ASCII representation of a
four digit number (offset 0x0034).

The matching library is identified by the it's creation time and
version, too. This is done in a similar format as that of the Add-In
compilation.

Library date is hold in eight bytes (offset 0x0038).

Library time is hold in four bytes (offset 0x0040).

Library version is hold in 4 bytes (offset 0x0044).

The next double word value is the offset of the Add-In icon from the
beginning of the header (offset 0x0048).

The next double word value is the offset of the Add-In list icon from
the beginning of the header (offset 0x004C).

The remaining bytes up to 0x0100 are usually preset with 0xFF. The
first 64 bytes are used for the comment one can enter during the
installation with PVM.exe. Again, this comment must be terminated with
0x00 so that one can have no longer comment than 63 characters.


Related library functions

LibGetUserMode() will cycle through all installed (user) Add-Ins
returning their mode and status.

LibGetMode() returns the mode of the currently running
Add-In. Although this function also returns a status word this is not
identical with that out of the header.

LibGetProgramName() can be used to get the name of installed Add-Ins.

LibGetLibVer() returns the concatenation of libdate, libtime and
libver.

LibGetMenuIcon() returns the menu icon of an Add-In.

LibGetListIcon() returns the list icon of an Add-In.

Beware: the pointer returned by LibGetMenuIcon() or LibGetListIcon()
is only guaranteed to remain valid until another library function is
called! So the best use of these functions is to obtain the pointer and
use it immediately to put the icon onto the screen with LibPutGraph()
or to copy the data into a buffer with far_memcpy().


Example code

This function will use the above mentioned library functions to get
information about the installed Add-Ins.

void ListAddIns()
{
  word mode_code;
  byte main_code, sub_code;
  word status;
  char name[16];
  char ver_str[17];
  byte far *pMenuIcon;
  byte far * pListIcon;
  byte condition;
  char text[80];
  
  condition = IB_DLFIRST_SRCH;
  
  while (1)
  {
      /* get mode information */
    LibGetUserMode(&mode_code,&status,condition);

      /* stop if there is no further Add-In */
    if(mode_code==0xffff) break;

    condition=IB_DLNEXT_SRCH;

     /* split up mode information into main and sub mode */
    main_code = mode_code >> 8;
    sub_code = mode_code;

     /* prepare display for icons */
    LibClrDisp();

    pMenuIcon = NULL;
    if (LibGetMenuIcon(&pMenuIcon,main_code,sub_code) && (pMenuIcon != NULL))
    {
      LibPutGraph(0,0,pMenuIcon);
    }

    pListIcon = NULL;
    if (LibGetListIcon(&pListIcon,main_code,sub_code) && (pListIcon != NULL))
    {
      LibPutGraph(0,30,pListIcon);
    }
    
    sprintf(text,"mode_code %04X",mode_code);
    LibPutProStr(IB_PFONT1,0,60,text,160);

    sprintf(text,"status %04X",status);
    LibPutProStr(IB_PFONT1,0,70,text,160);

    name[0] = 0;
    LibGetProgramName(name,main_code,sub_code);
    if ((name[0] != 0x00) /* we get "something" */
        && (name[0] != 0xFF)) /* but not hidden name of PVOS Add-In */
    {
      sprintf(text,"name %s",name);
      LibPutProStr(IB_PFONT1,0,90,text,160);
    }
 
    ver_str[0] = 0;
    if (LibGetLibVer(ver_str, main_code, sub_code)
        && (ver_str[0] != 0x00))
    {
      sprintf(text,"ver_str %s",ver_str);
      LibPutProStr(IB_PFONT1,0,100,ver_str,160);
    }

      /* dumb "wait for screen touch" function */
    LibPutMsgDlg("");
  };
}


Related constants (l_define.h)

The file "l_define.h" contains a lot of constants related to the
Add-In header. The section "MAIN MODE CODE" lists values used for the
main mode. For example there you will find the constant IB_MADDIN
defined as 0x08.

One will also find the values for the mode used in PVOS, for example
IW_MADDIN is defined as 0x0800.

Values for the sub mode depend on their main mode. As mentioned above
the sub mode for user Add-Ins is set during installation to the next
free (unused) value between 0x01 and 0x0F.
