Эта программа предназначена для анализа структуры файлов PV-OS 1600 формата
BIN.

Запуск программы:

pvosa [-p] [-f] file.in file.out
-p extract PVA's [no]
-f extract files [no]

Имеется в виду, что входной файл file.pva - файл PV-OS 1600 формата BIN,
а выходной file.out - текстовый файл с анализом структур входного файла.

Все ключи необязательны, так что программу можно запустить и так:

pvosa file.in file.out

В этом случае создается выходной текстовый файл, модули не извлекаются.


Описание ключей программы.

Ключ -P (PVA extract) включает извлечение файлов PVA, обнаруженных по
сигнатурам. Это может понадобиться для извлечения модулей из OS эмулятора,
которая имеет не совсем стандартный формат.
Пример использования ключа:

pvosa -p pvossim.bin pvossim.txt

Извлекаемые модули PVA имеют имена следующего вида: 0012ABC0.PVA, где 0012ABC0
- имя, соответствующее шестнадцатиричному смещению файла во входном файле
PVOS.


Ключ -F (Files extract) включает извлечение файлов, обнаруженных в корневом
каталоге (главном списке файлов) входного файла-образа PV-OS 1600. Это может
понадобиться для анализа их структуры. Имена файлов усекаются спереди до
максимальной длины имени DOS в 8 символов, например, libdriver.sys будет
извлечен с именем ibdriver.sys. Правильные имена файлов можно увидеть в выходном
текстовом файле в секции корневого каталога.
Пример использования ключа:

pvosa -f pvos103.bin pvos103.txt

В случае PV-OS эмулятора 1600 этот ключ использовать не рекомендуется, потому,
что размещение файлов в образе не соответствует записям в корневом каталоге.


Сообщения программы.

При успешном завершении программа создает выходные файлы и не выдает никаких
сообщений. В случае различных ошибок программа может выдавать следующие
сообщения:

I/O error.		- Ошибка ввода/вывода (открытия, создания файла,
				чтения или записи в файл).

В случае неправильного синтаксиса командной строки программа выдает сообщение:

pvosa [-p] [-f] file.in file.out
-p extract PVA's [no]
-f extract files [no]

Каждая структура в выходном файле начинается с заголовка следующего вида:

----------------------------------------------------------------
File offset: 002648B0h		- смещение от начала файла
Data end			- тип структуры
----------------------------------------------------------------

Структуры начала и конца данных.

Обозначают место во входном файле, где соответственно начинаются или
заканчиваются какие-либо данные. Смысл в том, что свободное (нераспределенное)
место в файле - образе PVOS заполнено байтами FF шестнадцатиричное, а начало
любых данных как правило выравнено на 16 байт.

Структура начала данных выглядит следующим образом:

----------------------------------------------------------------
File offset: 00000000h
Data begin
----------------------------------------------------------------
0000h: 43 41 53 49 4F 50 56 4F 53 32 30 30 55 AA 02 00 	CASIOPVOS200Uк..
0010h: 00 00 20 00 00 00 1D 80 00 00 00 00 00 00 00 04 	.. ....А........
----------------------------------------------------------------

Здесь в качестве типа структуры стоит "Data begin", а далее следует дамп
первых 32 байт обнаруженных данных.

Структура конца данных выглядит следующим образом:

----------------------------------------------------------------
File offset: 00000040h
Data end
----------------------------------------------------------------
0000h: 00 00 01 80 00 00 00 80 47 35 30 32 FF FF FF FF 	...А...АG502    
0010h: FF FF FF FF FF FF FF FF FF FF FF FF FF FF FF FF 	                
----------------------------------------------------------------

Здесь в качестве типа структуры стоит "Data end", а далее следует дамп
последних 16 байт обнаруженных данных и первых 16 после этого.


Структура первичного заголовка (сектора загрузки?) PV-OS.

Встречается в файле дважды, по смещениям 0 и 800 шестнадцатиричное. Выглядит
следующим образом:

----------------------------------------------------------------
File offset: 00000000h
PV OS header
----------------------------------------------------------------
Checksum: BA2Eh
0000h: PVOS signature		CASIOPVOS200Uк
000Ch: Syncword			55AAh
000Eh: Bytes per sector?	0200h
0010h: Allocated sectors?	00002000h, 00400000h
0014h: OS image length?		00001D80h, 003B0000h
0018h: First boot start?	00000000h, 00000000h
001Ch: Second boot start?	00000004h, 00000800h
0020h: Root directory start	00000420h, 00084000h
0024h: Some directory start?	00000440h, 00088000h
0028h: Root directory length	00000020h, 00004000h
002Ch: Some directory length?	00000020h, 00004000h
0030h: ?			00000400h, 00080000h
0034h: OS load address?		8C024800h, 00004A00h
0038h: OS start address?	8C024800h, 00004A00h
003Ch: ?			00001E80h, 003D0000h
0040h: ?			00000180h, 00030000h
0044h: ?			00000080h, 00010000h
0048h: Some signature?		G502
01FEh: Checksum			BA2Eh
----------------------------------------------------------------

Здесь в качестве типа структуры стоит "PV OS header", далее следует вычисленная
контрольная сумма структуры (Cheсksum: BA2Eh), затем - описание элементов
структуры.
В начале каждой строки первое слово - шестнадцатиричное смещение элемента
от начала структуры (не от начала файла). Во втором столбце приведены
предполагаемые назначения элементов структуры, в третьем - значение, взятое из
файла, через запятую в четвертом (если он есть) - интерпретация значения.

Сигнатура PVOS.

Находится в самом начале структуры и представляет из себя 12-байтную строку
"CASIOPVOS200".

Синхрослово.

Находится по смещению 0C шестнадцатиричное и представляет из себя слово 55AA
шестнадцатиричное, традиционно используемое во многих OS, BIOS для обозначения
начала/конца системных заголовков/таблиц или загрузочных секторов.

Слово по смещению 0E шестнадцатиричное всегда равно 200 шестнадцатиричное (512
десятичное) и наиболее логично (в связи с последующими полями) интерпретируется
как число байт в секторе (единице распределения пространства в образе PV-OS).

Двойное слово по смещению 10 шестнадцатиричное логичнее всего интерпретируется
как число секторов, распределенное (или требуемое для распределения) на
носителе (в данном случае во флеше) для размещения операционной системы. Во всех
изученных образах PV-OS имеет значение 2000 шестнадцатиричное.

Двойное слово по смещению 14 шестнадцатиричное практически однозначно
интерпретируется как длина образа PV-OS в секторах. Будучи умноженным на 512
(четвертый столбец), с точностью до байта совпадает с длиной файла-образа PV-OS.

Двойное слово по смещению 18 шестнадцатиричное всегда равно 0. Что это -
не совсем понятно. По аналогии со следующим словом (1C hex) может
интерпретироваться как адрес первой копии первичного заголовка (сектора
загрузки?) PV-OS.

Двойное слово по смещению 1C шестнадцатиричное логичнее всего интерпретируется
как адрес второй копии первичного заголовка (загрузочного сектора) PV-OS.
Будучи умноженным на 512 (четвертый столбец), с точностью до байта совпадает со
смещением до второй копии первичного заголовка PV-OS. Хотя может быть, что это
совпадение.

Двойное слово по смещению 20 шестнадцатиричное логичнее всего интерпретируется
как смещение в секторах от начала файла-образа PV-OS до корневого каталога
(главного списка) встроенных файлов (исполняемых модулей, драйверов, ресурсов)
PV-OS. В четвертом стобце приводится значение слова, умноженное на 512, то есть
смещение в байтах.

Двойное слово по смещению 24 шестнадцатиричное по аналогии с предыдущим можно
интерпретировать как смещение в секторах от начала файла-образа PV-OS до 
какого-то вторичного каталога (списка файлов), потому, что его значение
совпадает с концом предыдущего корневого каталога. В реальном файле-образе
PV-OS с этого смещения (88000h) и до 8C000h, то есть все 4000h байт (длина
корневого каталога, см. далее) данные отстутствуют. В четвертом стобце
приводится значение слова, умноженное на 512, то есть смещение в байтах.

Двойное слово по смещению 28 шестнадцатиричное логичнее всего интерпретируется
как длина в секторах корневого каталога (главного списка) встроенных файлов
(исполняемых модулей, драйверов, ресурсов) PV-OS. Во всяком случае, его
значение точно соответствует разности двух предыдущих слов, то есть конца и
начала корневого каталога. В четвертом стобце приводится значение слова,
умноженное на 512, то есть величина в байтах.

Двойное слово по смещению 2C шестнадцатиричное по аналогии с предыдущим можно
интерпретировать как длину в секторах вторичного каталога (списка файлов). Во
всяком случае, его значение точно соответствует разности между началом
размещения ресурсов (см. далее) и значению длинного слова по смещению 24h.
В четвертом стобце приводится значение слова, умноженное на 512, то есть
величина в байтах.

Двойное слово по смещению 30 шестнадцатиричное всегда равно 400h. Что это -
непонятно.

Двойные слова по смещению 34 и 38 шестнадцатиричное равны друг другу и логичнее
всего интерпретируются как адреса загрузки/старта операционной системы.
Во всяком случае, если при дизассемблировании началу кода PV-OS (смещение в
файле 4A00h) выставить адрес из этих длинных слов, все абсолютные адреса в коде
разрешаются правильно.
В четвертом столбце для этих слов приводится приведенное значение смещения
адреса в файле, то есть в вышеприведенном примере адрес 8C024800h соответствует
в файле смещению 4A00h.

Назначение двойных слов по смещениям 3C, 40 и 44 шестнадцатиричное непонятно.

По смещению 48 шестнадцатиричное находится четырехбайтовая сигнатура "G502".
Что это - непонятно. В PV-OS Casio PV-S x50/x60 встречается похожая сигнатура
"G500". Возможно, это какое-то внутреннее обозначение модели, для которой
создана PV-OS.

Далее вплоть до смещения 1FEh все заполнено FFh, а по смещению 1FE
шестнадцатиричное хранится слово-контрольная сумма первичного заголовка,
которая вычисляется как простая словная сумма первых 510 байт с расширением
до слова обнулением старшего байта.

Остальное место внутри 800 шестнадцатиричное байт первичного заголовка не
используется и заполнено FFh.

В начале каждой строки первое слово - шестнадцатиричное смещение элемента

Сигнатура PVOS.

Находится в самом начале структуры и представляет из себя 12-байтную строку
"CASIOPVOS200".

Слово по смещению 0C шестнадцатиричное логичнее всего интерпретируется
как число секторов, распределенное (или требуемое для распределения) на
носителе (в данном случае во флэше) для размещения вторичного заголовка PV-OS.
Будучи умноженным на 512 (четвертый столбец), с точностью до байта совпадает со 
смещением от начала вторичного заголовка до начала исполняемого кода.
Хотя может быть, что это совпадение.

Назначение слова по смещению 0E и двойных слов по смещениям 10 и 14
шестнадцатиричное непонятно.

По смещению 18 шестнадцатиричное находится четырехбайтовая сигнатура "G502".
Что это - непонятно. В PV-OS Casio PV-S x50/x60 встречается похожая сигнатура
"G500". Возможно, это какое-то внутреннее обозначение модели, для которой
создана PV-OS.

Дата компиляции PV-OS, 7 байт BCD формата.

Байты по адресам 1Ch-22h содержат закодированную в BCD информацию о дате
создания PV-OS. Они расположены в следующем порядке:

001Ch: Creation year		2002		Год компиляции PV-OS
001Eh:	- month 		12		- месяц
001Fh:	- day			11		- число
0020h:	- hour			15		- час
0021h:	- minute		59		- минута
0022h:	- second		02		- секунда

Вполне возможно, что байт по адресу 23h следует понимать как сотые доли
секунды, но он всегда равен нулю, так что особого смысла в этом нет.
Кодировка BCD означает, что старшие 4 бита байта кодируют старшую цифру
двузначного десятично го числа, а младшие четыре бита - младшую. То есть,
число 12h, равное десятичному 18, следует интерпретировать как 12.

Слово по смещению 24h содержит версию PV-OS. При этом старший байт в слове
хранит саму версию (то, что до точки), а младший - субверсию (то, что после
точки), то есть, например, слово "0A0B" следует интерпретировать как "10.11".

Назначение слова по смещению 26 и двойного слова по смещению 28
шестнадцатиричное непонятно. Двойное слово по смещению 28 в разных версиях
PV-OS различно, возможно, это какая-то контрольная сумма, но что считается
и как - непонятно.

Далее вплоть до смещения 1FEh все заполнено FFh, а по смещению 1FE
шестнадцатиричное хранится слово-контрольная сумма первичного заголовка,
которая вычисляется как простая словная сумма первых 510 байт с расширением
до слова обнулением старшего байта.

адресу 1000h). Выглядит следующим образом:

Здесь в качестве типа структуры стоит "BIOS vectors", далее следуют описания

В начале каждой строки первое слово - шестнадцатиричное смещение элемента
от начала структуры (не от начала файла). Во втором столбце приведены
предполагаемые назначения элементов структуры, в третьем - значение, взятое из

Векторы обработки функций BIOS (всего их 16) выглядят совершенно одинаково:

0000	mov.l	@(8,pc),r2	; Извлечь адрес таблицы функций
0002	shll2	r0		; Сдвинуть номер функции влево на 2 бита (* 4)
0004	mov.l	@(r0,r2),r0	; Извлечь из таблицы указатель функции
0006	jmp	@r0		; И пойти туда.
0008	nop			; Заглушка для delayed оператора
000С	data.l	h'8C07BEF4	; Адрес таблицы функций

и отличаются только адресом таблицы, из которой берутся указатели функций.
Эти-то адреса и отображаются в этой структуре в третьем столбце, в четвертом
- их смещения в файле-образе PV-OS.

следуют описания элементов структуры.
В начале каждой строки первое слово - шестнадцатиричное смещение элемента
от начала структуры (не от начала файла). Во втором столбце приведены
предполагаемые назначения элементов структуры, в третьем - значение, взятое из
файла, через запятую в четвертом (если он есть) - интерпретация значения.

В самом начале структуры находится сигнатура, она представляет из себя 9-байтную
строку "#PVOSAPL" с конечным нулем.

Следующий байт со смешением 9 всегда равен 1, и по аналогии с заголовком ELF
может содержать версию заголовка.

Назначение слова по смещению 0A шестнадцатиричное непонятно.

По смещению 0C шестнадцатиричное находится четырехбайтовая сигнатура "Z000".
Что это - непонятно.

По смещению 10 шестнадцатиричное размещается имя программы. Имеет вид текстовой
строки с именем программы, заканчивается нулем. Максимальная длина имени - 15
символов. Может отсутствовать, особенно в PVA файлах.

Назначение двойных слов по смещениям 20 и 24 шестнадцатиричное непонятно.
Двойное слово по смещению 24 шестнадцатиричное несколько напоминает совокупность
битовых флагов.

Двойное слово по смещению 28 шестнадцатиричное больше всего напоминает
совокупность битовых флагов, меняется от модуля к модулю, но назначение битов
не совсем понятно.

Двойное слово по смещению 2C шестнадцатиричное хранит адрес подпрограммы
инициализации программы перед запуском (__$_install_program). Вызывается перед
собственно запуском программы. В четвертом столбце приводится приведенное
значение смещения адреса в файле.

Двойное слово по смещению 30 шестнадцатиричное хранит адрес подпрограммы,
которая вызывается после завершения программы (__$_uninstall_program).
В четвертом столбце приводится приведенное значение смещения адреса в файле.

Двойное слово по смещению 34 шестнадцатиричное хранит адрес старта для
приложения (_main). У драйверов равно 0. В четвертом столбце приводится
приведенное значение смещения адреса в файле.

Двойное слово по смещению 38 шестнадцатиричное хранит адрес точки входа
для драйвера. У приложений равно 0. В четвертом столбце приводится
приведенное значение смещения адреса в файле.

По смещению 3C шестнадцатиричное находится имя программы в UNICODE. Вообще
говоря, оно уже не принадлежит структуре секции C_binaryinfo, а находится
в следующей за ней (для встроенных драйверов и проиложений, в общем случае это
не так) секции C_programinfo, но весьма полезно для идентификации модуля.

Описывает расположение и структуру файлов (исполняемых модулей, драйверов,
ресурсов и т.п.) в файле-образе PV-OS. Выглядит следующим образом:

Здесь в качестве типа структуры стоит "PV OS Root directory", далее
следуют описания элементов структуры.
В начале каждой строки первое слово - шестнадцатиричное смещение элемента
от начала структуры (не от начала файла). Во втором столбце приведены
предполагаемые назначения элементов структуры, в третьем - значение, взятое из
файла, через запятую в четвертом (если он есть) - интерпретация значения.

В самом начале структуры находится сигнатура, она представляет из себя
16-байтную строку "PVOS20-VALIDAREA". Вполне возможно, что она стоит в начале
каталога случайно, потому что встречается и в других местах файла-образа PV-OS.
Кроме того, смещение в бут-секторе (первичном заголовке) файла-образа PV-OS
указывает не на нее, а ровно на 16 байт позже.

Каждый элемент каталога (запись) занимает 40 шестнадцатиричное (64 десятичное)
байт в следующем порядке (смещения даны от начала элемента каталога):

Слово по смещению 0 обозначает номер, идентифицирующий каталог (если эта запись
описывает каталог), или равно FFFF, если запись описывает файл.

Слово по смещению 2 содержит идентификатор каталога, внутри которого расположен
описываемый файл, или же равно FFFF, если файл находится в корне (?).

По смещению 4 расположено UNICODE имя файла/каталога, максимальная длина имени
- 16 символов (32 байта).

Двойное слово по смещению 24 шестнадцатиричное содержит смещение в секторах от
начала файла-образа PV-OS до начала описываемого файла/каталога. В четвертом
стобце приводится значение слова, умноженное на 512, то есть величина в байтах.

Двойное слово по смещению 28 шестнадцатиричное логичнее всего интерпретируется
как число секторов, распределенное (или требуемое для распределения) на
носителе (в данном случае во флеше) для описываемого файла/каталога.

Двойное слово по смещению 2C шестнадцатиричное содержит длину описываемого
файла/каталога.

Дата создания файла, 7 байт BCD формата.

Байты по адресам 30h-36h содержат закодированную в BCD информацию о дате
создания файла/каталога. Они расположены в следующем порядке:

0030h: Creation year		2002		Год создания
0032h:	- month 		12		- месяц
0033h:	- day			11		- число
0034h:	- hour			15		- час
0035h:	- minute		59		- минута
0036h:	- second		02		- секунда

Вполне возможно, что байт по адресу 37h следует понимать как сотые доли
секунды, но он всегда равен нулю, так что особого смысла в этом нет.
Кодировка BCD означает, что старшие 4 бита байта кодируют старшую цифру
двузначного десятично го числа, а младшие четыре бита - младшую. То есть,
число 12h, равное десятичному 18, следует интерпретировать как 12.

Двойное слово по смещению 38 шестнадцатиричное больше всего напоминает
совокупность битовых флагов, меняется от записи к записи, но назначение битов
не совсем понятно.

Назначение двойного слова по смещению 3C шестнадцатиричное непонятно.

После последнего элемента каталога и до конца места, распределенного под
каталог (всего 4000h байт, см. описание первичного заголовка) все заполнено
байтами FF шестнадцатиричное, только последние 16 байт из этого пространства
содержат 16-байтную строку "PVOS20-VALIDAREA".

В начале каждой строки первое слово - шестнадцатиричное смещение элемента

Сигнатура PVA, ASCII, байты 0-Bh

Имеет вид текстовой строки "PVAPLHEDV20", заканчивается нулем.


Версия заголовка?, слово? (байт?).

Слово по смещению 0Ch (или байт по смещению 0Dh) всегда равны 1.
По аналогии с заголовком ELF это может быть версия заголовка.

Далее вплоть до смещения 3Ah заголовок заполнен нулями. Слово по смещению 3Ah
(или байт по смещению 3Bh) всегда равны 1. Что это - непонятно.


Смещение до заголовка ELF, двойное слово.

Двойное слово по смещению 3Ch хранит смещение от начала файла до заголовка ELF.
Оно может принимать три значения:
1) 0A8h (если файл не содержит ни одной иконы),
2) 150h (если файл содержит только большую икону),
3) 1A0h (если файл содержит обе иконы).


Вид файла, слово.

Слово по смещению 40h содержит вид файла. Программа setheader.exe из SDK
PV-S1600 упоминает об этом буквально следующее:
	-m[1-3]   : program mode [1:PV,2:CP,3:PV/CP]
PV - это, видимо, Pocket Viewer, остальное непонятно. В модулях, выдернутых
из файла операционной системы, встречается значение этого слова = 5.
Возможно, это признак исполняемого модуля, встроенного в систему.


Тип файла, слово.

Слово по смещению 42h содержит тип файла. Программа setheader.exe из SDK
PV-S1600 упоминает об этом буквально следующее:
	-p[A|D]   : program type A=Application , D=Driver
При этом значение слова может быть:
	0  - соответствует Application,
	2 - Driver.


Слово по смещению 46h (или двойное слово по смещению 44h) всегда равны 48h.
Что это - непонятно. По аналогии с заголовком ELF это может быть смещение до
начала имени.


Имя программы, ASCII, байты 48h-87h

Имеет вид текстовой строки с именем программы, заканчивается нулем.
Максимальная длина имени - 31 символ. Оставшиеся 32 байта (по адресам 68h-87h)
всегда равны 0, это остаток буфера под 31-символьное имя в unicode, потому, что
программа putname.exe из SDK PV-S1600 может помещать в заголовок имя либо
в однобайтовой кодировке, либо в двухбайтовой.


Версия программы, слово.

Слово по смещению 88h содержит версию программы. Программа setheader.exe из SDK
PV-S1600 упоминает об этом буквально следующее:
     -vpMMNN   : program version
При этом старший байт в слове хранит саму версию (то, что до точки, или, как
в ключе MM), а младший - субверсию (то, что после точки, NN), то есть, например,
слово "0A0B" следует интерпретировать как "10.11".


Версия библиотек программы, слово.

Слово по смещению 8Аh содержит версию библиотек программы. Программа
setheader.exe из SDK PV-S1600 упоминает об этом буквально следующее:
     -vlMMNN   : library version
При этом старший байт в слове хранит саму версию (то, что до точки, или, как
в ключе MM), а младший - субверсию (то, что после точки, NN), то есть, например,
слово "0E11" следует интерпретировать как "14.17".


Длина тела ELF, двойное слово.

Двойное слово по смещению 8Ch хранит длину тела ELF, то есть число байт от
начала заголовка ELF до конца файла. Таким образом, общая длина файла должна
быть равна:
	содержимому двойного слова по смещению 3Ch (начало ELF) +
	+ содержиме двойного слова по смещению 8Ch (длина ELF).


Дата компиляции файла, 7 байт BCD формата.

Байты по адресам 90h-96h содержат закодированную в BCD информацию о дате
создания файла, точнее, дату и время того момента, когда у файла был создан
заголовок. Они расположены в следующем порядке:

0090h: Creation year		2002		Год компиляции программы
0092h:	- month 		12		- месяц
0093h:	- day			11		- число
0094h:	- hour			15		- час
0095h:	- minute		59		- минута
0096h:	- second		02		- секунда

Вполне возможно, что байт по адресу 97h следует понимать как сотые доли
секунды, но он всегда равен нулю, так что особого смысла в этом нет.
Кодировка BCD означает, что старшие 4 бита байта кодируют старшую цифру
двузначного десятично го числа, а младшие четыре бита - младшую. То есть,
число 12h, равное десятичному 18, следует интерпретировать как 12.

Слово по смещению 98h всегда равно 1. Что это - непонятно.

Слова по адресам 9Ah-9Ch содержат высоту и ширину большой иконы соответственно.
Обе величины - в точках. Если большая икона отсутствует, оба эти слова равны
FFFFh. Размер большой иконы всегда 28х45.

Слово по смещению 9Eh всегда равно 0. Что это - непонятно.

Слова по адресам A0h-A2h содержат высоту и ширину малой иконы соответственно.
Обе величины - в точках. Если малая икона отсутствует, оба эти слова равны
FFFFh. Размер малой иконы всегда 20х27.

Слово по смещению A4h всегда равно 0. Что это - непонятно.

Слово по смещению A6h чаще всего равно 0, но иногда встречаются другие значения.
Что это - непонятно.
